# Business Technologist Roadmap

A self-directed learning project to build the profile: **someone who can understand a business problem, design the technical solution (AI + software), build it, and get it adopted.**

Not "AI person." Not "software engineer." A **business technologist**.

## Files in this project

| File | Purpose |
|---|---|
| `ROADMAP.md` | The 5-part skill map and technical stack layers. Your reference map. |
| `PROJECTS.md` | Project-based learning path — each project trains multiple layers at once. |
| `PROGRESS.md` | Checklist tracker. Update as you go. |
| `ARCHITECTURE.md` | Practice space for solution-architecture thinking (the "draw the boxes" skill). |

## How to use this with an agent (Claude Code, etc.)

1. Open this folder as a project.
2. Start with `PROGRESS.md` — it tells the agent (and you) what phase you're in.
3. Pick the next unchecked item in `PROJECTS.md`.
4. Ask the agent to help you scope and build that project, referencing `ROADMAP.md` for which stack layers it should exercise.
5. After finishing a project, fill in one `ARCHITECTURE.md` diagram for it — force yourself to explain every box.
6. Check it off in `PROGRESS.md`, commit, move to the next one.

## The core mental model

```
Business problem
   ↓ Analyze it        (Business & Finance)
   ↓ Design solution   (Architecture)
   ↓ Build it          (AI, Data & Technical Systems)
   ↓ Explain it        (Communication)
   ↓ Sell it           (Influence & Sales)
   ↓ Deploy it         (Enterprise Systems)
   ↓ Measure ROI       (Business case thinking)
```

Every project you pick should touch as many of these steps as possible — not just the "build it" step. That's the whole point of this framework: most people only ever practice "build it."

## Ground rule

Don't study skills in isolation. Pick a real (even tiny) problem, and let the skills come to you as you need them, in the order in the diagram above. See `PROJECTS.md` for starting points.
